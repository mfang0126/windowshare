# 0003 - 共享生命周期：单一共享、谁开谁管、老板可关闭任意共享

状态：accepted（2026-11-12 老板当面定稿）

多个 Bot 在同一台 Mac 上为同一位老板工作，共享的开始、结束和归属必须有一套固定规则，否则 Bot 之间会互相关掉对方的共享，或留下没人管的共享和还能打开的旧链接。术语见 [../../GLOSSARY.md](../../GLOSSARY.md)。

## 规则

1. 同一时间只允许一个共享。谁开的谁管；agent 之间不能互相关闭对方的共享。
2. 共享从 agent 发出开始命令起算。结束条件：
   - 开的 agent 自己结束；
   - 开它的进程退出（持续分享模式除外）；
   - 老板点「完成」；
   - 老板口头让任意 Bot 关（只有老板能越过「谁开谁管」）；
   - 到 12 小时上限（提前 10 分钟提醒）；
   - Mac 退出。
3. 已有共享时其他 agent 申请，立即回「正在被 X 使用」（写明谁开的、开了多久），不排队。
4. 通知发到开这次共享的 agent，由它转告老板；老板口头关掉时也通知原 agent。agent 做完但持续分享仍开着时要通知老板。
5. 共享结束后链接立即失效，不可复用；下次重新开新链接。
6. 用户可要求「持续分享」，此模式不随开启进程退出而结束，只按老板关闭/12 小时/Mac 退出结束。

## 原因

- 单一共享：同一时间只保留一个共享，使当前共享的窗口和开启者保持明确，减少多个 Bot 同时发起共享带来的混淆。
- 谁开谁管：开启者最清楚这次共享为什么开、何时可以关；别的 Bot 关掉它会打断正在进行的事。老板是例外，因为共享是给老板用的。
- 不排队、立即回答：申请方马上知道谁占着、占了多久，可以自己决定等、换做法或去问老板；避免申请方在未获知占用情况时等待。
- 通知走开启者：由开启者转告通知，便于老板从办理这件事的 Bot 获知共享状态；老板口头关闭时也通知开启者，使它知道共享已经结束。
- 进程退出即结束、链接用完即废：普通共享随开启进程退出而结束，避免进程结束后共享仍继续；持续分享按第六条结束。共享结束后使链接失效，避免旧链接继续用于访问共享。
- 持续分享和 12 小时上限：老板需要一个不随 Bot 进程消失的共享，但任何共享都要有到点自动结束的兜底，提前 10 分钟提醒，便于老板安排收尾。
