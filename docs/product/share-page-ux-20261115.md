# 分享页的产品要求（2026-11-15）

这是 Ming 今晚确定的分享体验，也是本次及以后改动的需求依据。现在分享页还保留操作按钮、状态和调试信息，手机输入与后台窗口选择也需要完善。

## A. 分享页只有一块屏幕

正常分享只有一个链接加一块屏幕。打开链接就显示画面，一个按钮都不留。刷新、Interact / View、指针模式、键盘、关闭、完成、取消、Agent 请求和倒计时全部放进 debug 模式；调试信息、计数和诊断面板也只在 debug 模式显示。

用户点画面就算要操作，自动接管，安全检查照保留。关掉网页就算结束，Bot 收到事件。正常页关闭或刷新会结束这次共享；连接中断自动恢复观看。调试入口在链接末尾加 `#debug`。收到关页信号时发送 `left`（`page_closed`）和 `share_ended`（`page_closed`），不把关页当成任务成功；浏览器被杀或离线未送达信号时只能记录断连。

## B. 手机上怎么看、怎么操作

默认铺满页面宽度。双指放大，双击在铺满宽度和放大到点击处之间切换，不加 fit 按钮。优先由 Bot 在分享前把 Mac 窗口调成手机比例。

点一下就是点击。点到输入框自动弹出手机键盘，支持中文和粘贴，画面自动滚到键盘上方；验证码能从键盘提示直接粘贴。

没放大时拖动就是滚动 Mac 页面；放大后拖动是移动画面。长按先不做。

断线自动重连，只在角落显示一个小的「重连中」。大约 5 分钟没操作就自动收回控制权。链接只能用一次。密码框不留记录、不截图。密码画面不能留在证据、日志或输入门禁缓存；人的实时画面仅传输，不留存，不放宽帧与几何门禁。现行管线尚未分离实时帧与授权缓存，密码输入新要求待实现。

## C. 自动选地址

默认用 Tailscale 地址，在家和外出用同一个链接；连不上就自动换成本地局域网地址。用户改成哪种就记住，以后默认用这种。不开公网，不动 Tailscale 配置。

host 在发链接前探测本机各私有地址的 HTTP 和控制监听端口，优先选择 Tailscale，失败才选 LAN。此探测只能证明 host 侧监听可达，不能证明远端手机有同一路由。分享命令加 `--prefer-network lan` 记住局域网偏好，加 `--prefer-network tailscale` 改回；偏好存在 `com.windowshare.network` UserDefaults 的 `entryPreference`。

已加载并认证的页面断线后，可用一次性恢复凭据切到另一已探测地址；恢复凭据放 URL fragment，兑换后清除，不进查询参数或日志。首次打开的地址完全不可达时页面尚未加载，无法跨网自动切换，需用可达地址的新链接。

## D. 给 AI 用的路径

AI 主要取单帧，不录像；录短片只用在 debug 里排查闪烁和卡顿。

Orca 或 Skills 拿到链接就取帧、发点击或输入；遇到登录就把链接交给用户，等用户关掉页面。Ego 后台 Space 里的页面必须能选到。

本机 Agent 命令：`Scripts/windowshare-agent frame` 输出单帧到 stdout，`click 0.5 0.5` 使用归一化坐标，`text` 从 stdin 读文本并逐段确认，`handoff --reason "请完成登录后关闭分享页"` 返回人用链接并等关页事件。依赖 Python 的 websocket-client；凭据从 agent.json 读取，不进入命令行或日志。Agent 的连接票据、租约和输入走与人相同的控制通道，密码/未知焦点拒绝 Agent 取帧与输入，转入交人路径；关页只表示交接结束，不表示业务成功。

Agent 焦点分类只读取目标窗口的 AX role/subrole；secure text field、无法读取或无法确认目标焦点时拒绝。后台页面的 AX 可用性与密码画面严格不缓存要求仍需后续验证和管线改造，不把已有截图接口当成密码安全验收。

## 验收怎么测

帧率在正常分享页的接收端按真实呈现的帧数来数，前台、后台、恢复三段都要测；人用和 Agent 用两条路径都要覆盖。

帧率暂不处理，Ming 认为现在已经够用。
