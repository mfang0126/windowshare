# Bot 交给人操作的场景（2026-11-14）

这是 Ming 15:07 口述场景的需求记录，不代表方向冲突已裁决，也不代表功能已实现。

## 目标与验收

1. **后台**：平时 WindowShare 隐藏在 Android 手机后台，共享窗口偶尔发两张画面就够，刷新率不必高。验收时记录后台实际接收画面、捕获与发帧节奏和电量；系统暂停时须如实显示或记录，不把后台持续更新当作浏览器保证。
2. **需要人时**：Bot 需要 Ming 时（例如登录），把对应页面送到手机上，Ming 一看就知道该做什么。验收时从 Bot 指定窗口和原因开始，在手机看到对应任务并进入正确页面；通知权限关闭、离线和链接过期时提供明确可恢复路径。自动强行置前还是点击通知进入，待 Ming 决定。
3. **打开后**：Ming 打开后手机端实时显示，24 或 30 帧均可，能看清即可。验收在目标 Android、实际网络和代表性窗口操作中测量端到端实际显示帧率与延迟；目标为稳定 24–30 fps，记录窗口、网络、时长和掉帧，不以捕获设置替代实测。
4. **清晰度**：清晰主要取决于分辨率。验收在目标手机上检查代表性登录表单和文字，记录源窗口、输出像素、手机尺寸与缩放；文字、控件与操作位置清楚可用，清晰度标准及最低字号待约定。压缩、网络和显示缩放也会影响效果。
5. **由人决定结束**：Ming 接手后自己决定何时关；在手机明确关闭后，Bot 尽快收到提醒或回调，自己回收会话与资源。验收记录关闭动作到 Bot 收到事件的时间，验证旧链接失效、输入撤销、画面和捕获停止、共享锁及相关进程和登记按归属释放。普通切后台、断网、系统杀进程与明确关闭要分开，不能把断线误判为用户完成；异常退出不能保证立即送达，应有可恢复的状态查询和兜底。可接受的通知时限待确定。

## 与现有方向的冲突

`INTENT.md`「不做」原文包括：“系统共享面板（`SCContentSharingPicker`，2026-10-29 删除）、agent 交接协议的扩展、逐次授权、模拟授权、自动登录、pattern 录制、推送通知、远程解锁、iOS 专项、发布门槛和真机验收清单。” 新场景需要 Bot 通知手机、手机结束后通知 Bot；推送通知和交接协议扩展可能触及现行禁止范围。Ming 需决定是否修改方向、允许哪些通知与协议机制，以及「弹到手机上」是否可由用户点击通知完成。现有方向保持原样，以下仅为条件性建议，不构成授权实施。
